## 4. Objective implementation audit

Let `z_i` be L2-normalized 3D embeddings and `s_ij=z_i·z_j/T`. Actual definitions are in `src/neurobridge/losses/infonce.py:7-162`; dispatch in `staged_shared_latent.py:906-931` and `real_monkey_validated.py:420-453`.

| Objective | Actual anchor/positive/negative and loss | Boundary, mask and semantic audit |
|---|---|---|
| Soft relational (`soft`) | Each of 1024 windows is anchor. Target `q_ij ∝ exp(-d_ij/T_meta)` for all off-diagonal batch windows; loss `-mean_i Σ_j q_ij log softmax_j(s_ij)`, self excluded. `d` averages normalized within-trial time-distance and circular condition-distance, weights 0.5/0.5. Synthetic `staged_shared_latent.py:611-624`; real `real_monkey.py:729-741`. No binary negatives; every off-diagonal window enters the denominator. | Train batch subset is train trial IDs, held-out validation batch subset validation IDs; cross-trial pairs allowed by design. Real time normalization is hard-coded `/599.0` versus synthetic `/(trial_length-1)`; matches current 600-bin recording (`real_monkey.py:729-741`, `stage02_windows/metadata.json`) but is not generalized. Target metadata uses only time and condition, not measured position/velocity. |
| Supervised/condition InfoNCE (`infonce`) | Positives are all other same-label samples in batch. Per anchor, average negative log probability over positives; denominator contains all 1023 nonself windows, including same-label positives (`infonce.py:14-43`). | Same-condition samples are **not** mistakenly masked as negatives in this objective. Anchors with no same-label positive excluded; if none in batch, returns differentiable zero. Labels are per-trial condition; no val/test labels enter training due subset. |
| Time-offset triplet (`time_contrastive_blocks`) | One anchor at trial/time center `(r,t)`, positive `(r,t+10)` in same candidate split, one sampled negative per anchor from all valid windows in same split. Loss `-mean cos(z_ref,z_pos)/1 + mean logsumexp_j cos(z_ref,z_neg_j)/1` over 1024 negative columns (`sampling/cebra_time.py:49-111`; `infonce.py:97-126`). | Positive is forward +10, not ±10. Invalid shifted/padded windows excluded from anchor/positive pool. Negative may be same trial/condition or nearby; sampler avoids its own anchor/positive only when pool>2, but loss contrasts each anchor with *all* batch negatives. Triplet formulation does not put the designated positive in the denominator, so its `ln(1024)` uniform baseline is not exactly the standard positive-plus-negatives softmax objective. |
| Behavior/condition triplet (`behavior_contrastive_blocks`) | Anchor from valid split; positive sampled from same discrete condition, distinct anchor; negative sampled uniformly from whole valid split, no label exclusion (`sampling/cebra_behavior.py:55-109`). Same triplet loss and 1024 negative columns as time objective. | Labels are `target`/`labels` condition only, not progress, position, velocity. Negatives may share condition/anchor/positive. This is a **likely false-negative semantic issue** if the intended invariant is condition similarity (Section 5), but cannot be silently redefined. |

All four use cosine scores after `F.normalize` inside the loss (`infonce.py:7-11,120-126`), and neural encoders also have `normalize=True` in training (`staged_shared_latent.py:827`; `real_monkey_validated.py:655-657`). No train/test mixing in data loaders (`staged_shared_latent.py:764-885`; `real_monkey_validated.py:638-718`). Stride-1 raw windows within a trial overlap, including many off-diagonal pairs; this is not a cross-split leak because splits are by trial. The objectives have different supervision and candidate semantics, so raw loss levels must **not** be compared as if on one scale.

## 5. Behavior-contrastive audit

**FACT:** `CEBRASupervisedWindowDataset` makes same-condition positives (`sampling/cebra_behavior.py:55-92`) and whole-pool negatives (`:72,93-100`); the loss treats every `negative` column as repulsive (`losses/infonce.py:120-126`). For one anchor of class `c`, expected matching negative fraction is `n_c/N`; averaged over anchors it is `Σ_c (n_c/N)^2`. Existing cached train labels give Synthetic A 0.1251, Synthetic B 0.1251, real total-65 0.1303; validation approximately 0.1300. For B=1024 this is ~128 or ~133 matching negative columns per anchor (not necessarily distinct). Evidence: `...seed42_synthetic/stage02_windows/windows_{A,B}.npz`, `...seed123_real_total_65/stage02_windows/windows.npz`, their split JSON; real train class counts `[13340,11020,9280,11020,7540,10440,8120,6960]`. Since negatives are with replacement, exact per-batch counts vary. **INFERENCE:** likely false-negative pressure under a condition-invariance interpretation; not evidence that it uniquely explains the Transformer pathology. Excluding them would change the frozen scientific objective, not be an invisible software fix. Also note the negative may equal its anchor/positive (`cebra_behavior.py:93-100`), unlike time sampler; expected self probability is approximately `1/N` per draw.

## 6. Time-offset audit

**FACT:** `_load_real_window_dataset`/`_window_subject` carry center `time_id` and `trial_id`; `CEBRATripletWindowDataset` resolves `(same trial, t+10)` via a lookup, not flattened index arithmetic (`sampling/cebra_time.py:49-70`; `real_monkey.py:498-519`; `staged_shared_latent.py:519-553`). With window length 21, centers 10 apart share **11 of 21 raw bins**; centers 1 apart share 20/21. Valid masks require a complete unpadded window and, for shifted B, complete observed bins (`real_monkey.py:512-519`; `staged_shared_latent.py:538-544`). The negative pool is same-split, valid windows but unrestricted by temporal distance (`cebra_time.py:75-98`); adjacency is possible. Positive +10 is used in both datasets (`SharedLatentStageConfig.cebra_time_offset=10`, `RealMonkeyConfig.cebra_time_offset=10`; saved configs). This objective offset is a *within-population training relation*, not the imposed synthetic A/B observation lag (`staged_shared_latent.py:402-410`) or controlled real B shift (`real_monkey_lag_eval.py:267-276`). Controlled lag uses common trial/time support and positive lag means compare A(t) to B(t+lag) (`real_monkey_lag_eval.py:163-214,417-434`). **INFERENCE:** current center indexing and validity checks rule out the obvious cross-trial/off-by-one/padded-window route in the inspected code; same-trial overlap can still make temporal discrimination easier and negatives may be adjacent. No source evidence of an A/B reference-index mismatch was found; existing boundary-peaked lag curves remain a scientific failure requiring a separate interpretation, not proof of an index bug.

## 8. CNN optimization/configuration

**FACT:** Both datasets use 21-bin, stride-1, 3D unit embeddings during optimization, AdamW `lr=1e-3`, `weight_decay=1e-4`, batch 1024, no microbatch (`staged_shared_latent.py:70-123,827-885`; `real_monkey_validated.py:591-659,678-734`). Synthetic: cap 4000, check every 400, minimum 800, patience 3, relative improvement 0.001 (`staged_shared_latent.py:113-118,902-968`); real: cap 4000, every 150, min 750, patience 5, relative improvement 0.001 (`real_monkey_validated.py:44-62,800-876`). Held-out `model.pt` selects the **lowest raw validation loss**, which can predate the first patience-eligible step; full-sample uses fixed `N_best` from held-out and no validation (`staged_shared_latent.py:773-785,946-1002`; `real_monkey_validated.py:818-913`). **INFERENCE:** the two domains have unequal validation/stop schedules, so optimizer-update exposure is not matched even though caps/batch sizes are; this is a protocol-comparability qualification, not a license to change V2.

CNN: input `(B,21,N)` transposed to Conv1d channels; 64 hidden, initial kernel 3/GELU, 2 residual Conv1d+GELU+Dropout(0), global average pool, linear 64→3, L2 normalization (`models/temporal_cnn.py:250-385`; constructors `staged_shared_latent.py:635-643`, `real_monkey.py:700-708`). No normalization layer in CNN blocks. Per-fit `compute.json` parameter examples: Synthetic A 160-channel 55,683; real total65 37,443; real A32 31,107; B33 31,299. `train/loop.py:291-435` supports optional clipping but V2 callers do not pass it; no scheduler/AMP/autocast in V2 fit functions. Initialization is PyTorch module default after seeding; no custom initializer found. Real first-batch gradients and parameter movement are logged (`real_monkey_validated.py:784-795,957-960`).

For real R0, the saved Stage-4 NPZ does not carry `lag_valid`; these diagnostics use the same test/validation window scope as real Stage-5 (`real_monkey.py:1094-1118,1236-1246`), including trial-edge center-padded windows. The real total65 seed123 collapsed Transformer-behavior `compute.json` nevertheless records a nonzero first-gradient norm `0.00684`, first-step parameter change `0.3167`, and total parameter change `8.4605` (`...seed123_real_total_65/stage03_models/held_out/transformer_behavior_contrastive_blocks/compute.json`): it was updated, not simply skipped by the optimizer.

1. **Protocol decision, not silent bug fix:** define the scientific meaning of `behavior_contrastive_blocks` same-condition negatives before searching temperature. Until resolved, do not claim exact source-level replay of historical real fits.
3. **Evaluation design:** reserve a validation-only tuning criterion and keep existing test metrics out of search decisions. Current decoder/model selection is validation-based, but the researcher has seen V2 test results (`real_monkey.py:1261-1319`; `real_monkey_validated.py:813-821`). A new confirmatory evaluation must account for that test reuse; do not tune on Stage-5 held-out scores and then call the same scores unbiased confirmatory evidence.
4. **Failure criterion:** specify a geometry + loss + task diagnostic criterion for near-collapse, not PR alone. Existing real Transformer failures are reproducible in saved artifacts (Section 10); a temperature hypothesis is unproven. Do not delete/drop failed configurations post hoc.

None of these authorizes retraining, changing temperature, changing negative sampling, or editing current V2. The upstream 40-ms smoothing boundary procedure is also unresolved (`real_monkey.py:373`; Section 11) and limits strong leakage claims; it need not block read-only proposal formulation.
